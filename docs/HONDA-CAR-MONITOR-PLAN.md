# Honda Car Monitor — 项目方案

## 项目目标

开发一款可安装在 Android 车机上的中文只读诊断应用，优先适配用户的 2019 款本田思域劲动版原厂中控屏。应用分为“车机自身信息”和“车辆 ECU/OBD 数据”两类数据源，绝不把模拟值标成真实数据。

## 已有资料与复用边界

- 参考资料库《本田黑科技_7.6.0_逆向分析.md》：样本为 HondaHack 7.6.0 二次修改版，报告记录了车机服务、仪表显示、音频焦点、方向盘按键等线索。
- 既有 GitHub 项目 `qiangge5586-a11y/my-android-app-` 是 Android 只读车机底层/热点兼容性检测 APK，最低 API 17；可复用其车机信息采集与只读安全原则，但它不是车辆 ECU 数据接口。
- HondaHack 报告中的 root/Xposed、系统分区改写、远程卸载/吊销等高风险实现不移植到本项目。

## 数据源分层

### A. 车机本机信息（无需 OBD 适配器）

- Android 版本、API Level、设备型号、品牌、板级、硬件、固件、内核
- 屏幕分辨率、密度、刷新率（系统允许时）
- CPU 架构/核心数/负载、内存总量与可用量
- 存储总量与可用量
- 电池状态/温度/电压（若车机系统暴露）
- 网络接口、Wi-Fi 状态、蓝牙状态
- 已安装应用、包名、版本（仅展示用户可见信息）
- 运行日志与诊断报告导出（本地保存，不默认上传）

### B. 车辆 ECU / OBD-II 数据（需要实际接口）

- 车速、发动机转速、冷却液温度、进气温度
- 计算负荷、节气门位置、进气歧管压力/空气流量（ECU 支持时）
- 控制模块电压、燃油相关参数（ECU 支持时）
- 故障码读取、冻结帧、故障码说明；清码操作默认二次确认并提示风险

优先采用标准 OBD-II 适配器（蓝牙经典、BLE 或 Wi-Fi，按实际硬件选择）和 ELM327 兼容协议。适配器型号、协议和车辆 ECU 支持情况未验证前，所有车辆数据页显示“未连接/不支持”，不得伪造真实值。

### C. 车机厂商车辆属性接口（可选）

仅当目标车机确实运行 Android Automotive OS，且厂商公开/授权 CarPropertyManager 及相应权限时才接入。普通 Android 中控屏不等于 Android Automotive OS；不能假设 CarPropertyManager 可用。

## 技术方案

- Kotlin + Android 原生 UI，中文优先，横屏/大触控目标，适配 800×480、1024×600 等分辨率但以实机为准。
- minSdk 初步沿用既有诊断项目 API 17 的兼容目标；最终依赖与 SDK 版本以构建验证为准。
- 架构：UI / Domain / Data 三层；数据源接口分离为 HeadUnitInfoSource、ObdDataSource、VehiclePropertySource。
- OBD 通信采用独立连接状态机、超时/重试、PID 能力探测；数据标注来源、时间戳、有效性。
- 所有采集默认本地处理；不联网上传 VIN、位置、故障码或日志。
- 默认只读；不写 ECU 参数、不执行 root 命令、不修改 /system、不安装 Xposed、不关闭车机安全服务。
- 行车中限制复杂交互；仪表只显示必要信息，停车后才允许导出/清码等操作。

## 页面规划

1. 首页：连接状态、车机概况、车辆数据源状态。
2. 车机信息：系统、硬件、CPU、内存、存储、屏幕、网络。
3. 实时车辆数据：转速、车速、水温、电压等卡片和仪表。
4. 传感器/PID：支持项列表、实时值、单位、更新时间。
5. 故障诊断：读取 DTC、冻结帧、清码确认。
6. 数据记录：本地 CSV/JSON 导出。
7. 兼容性报告：车机型号、Android 版本、屏幕参数、OBD 连接与 PID 支持情况。

## 里程碑

- M0 需求与设备能力确认：确认车机 Android 版本/型号、屏幕分辨率、OBD 适配器类型。
- M1 车机信息采集：实现无需外设的本机信息页和兼容性报告。
- M2 OBD 连接层：蓝牙/Wi-Fi 连接、协议识别、PID 探测。
- M3 实时数据仪表：真实 PID 映射、单位换算、曲线和记录。
- M4 故障诊断：DTC/冻结帧/清码安全流程。
- M5 目标车机实测：横屏、启动、权限、蓝牙稳定性、长时间运行与驾驶安全验证。
- M6 输出中文 APK、校验值、安装说明和 GitHub 发布记录。
